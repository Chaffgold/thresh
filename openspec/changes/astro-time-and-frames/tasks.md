# Tasks — Astrodynamic Time Scales and Reference Frames

> Phases follow design.md's Migration Plan: the epoch type first (everything downstream consumes it), then the frames module with its golden validation (additive, no callers touched), then the single atomic BREAKING step (epoch migration + frame enforcement + call sites, with the benchmark-invariance check in the same commit), then tagging/docs. The falsifiable exit criterion is task 5.2.

## 1. astro-time — `thresh-core/src/time.rs` (design Decision 1)

- [ ] 1.1 Add `hifitime` (4.x, `serde` feature) to the workspace and `thresh-core`; define the `Epoch` newtype wrapping `hifitime::Epoch` with constructors (`from_gregorian_utc`, `from_iso8601`, `from_jde_utc`, `from_jde_tt`), accessors (`to_jde_utc_days`, `to_jde_tt_days`), `Sub<Epoch> -> f64` seconds and `+ f64` seconds stepping, and doc comments stating the scale of every input/output. Record the license rationale (MPL-2.0 dependency acceptable; AGPL nyx-space still rejected) in the module doc.
- [ ] 1.2 Scale-offset tests: 2020-01-01T00:00:00 UTC read back in TAI (+37 s), GPS (+18 s), TT (TAI + 32.184 s) (spec: "Scale conversions agree with published offsets"); JD round trip in UTC to sub-microsecond with the TT reading offset by TT−UTC (spec: "Julian-date round trip in a stated scale").
- [ ] 1.3 Leap-second test: elapsed time across 2016-12-31T23:59:59 UTC → 2017-01-01T00:00:00 UTC is 2 s (spec: "Interval across a leap second"); stepping test: `(e + 60.0) − e == 60.0` exactly (spec: "Stepping an epoch by dt").
- [ ] 1.4 Serde: serialize as an ISO-8601 UTC string with explicit scale designation; round-trip test recovers the epoch exactly (spec: "Serde round trip"). Keep `Timestamp` untouched with a doc note pointing absolute-time users at `Epoch` (design Open Question resolved: leave, don't deprecate).

## 2. frames module — `thresh-core/src/frames/` (design Decisions 2–4)

- [ ] 2.1 Rotation legs as phase helpers, each ≤ 15 complexity: IAU-76 precession angles (ζ, θ, z) and matrix; IAU-1980 nutation as a const 106-term table (source edition cited inline) with a table-driven evaluation of Δψ, Δε and the mean obliquity; GMST (epoch-taking form, UT1≈UTC documented) and GAST via the equation of the equinoxes; optional polar-motion W(xₚ, yₚ). Per-leg unit tests against Vallado intermediate values.
- [ ] 2.2 `Frame` enum (Gcrf, Mod, Tod, Teme, Pef, Itrf), `FrameRotation { r: Matrix3, r_dot: Matrix3 }`, and the `FrameProvider` trait (`rotation(from, to, epoch) -> Result<FrameRotation, FrameError>`); `Iau76Fk5Provider { delta_ut1, polar_motion }` with zero defaults and documented accuracy floors (≤ ~430 m ECEF longitude from |ΔUT1| ≤ 0.9 s; ≤ ~15 m polar motion). Composition builds any from→to pair through the chain without manual leg chaining.
- [ ] 2.3 TEME junction: TEME↔TOD via the equation of the equinoxes, TEME→PEF via GMST; test that the TEME→GCRF displacement at a modern epoch is kilometre-scale for a LEO-magnitude position and round-trips within tolerance (spec: "TEME and GCRF differ by precession and nutation").
- [ ] 2.4 State+covariance transform forms: 6×6 Jacobian `[[R, 0], [Ṙ, R]]` with Ṙ = ω⊕-rate term for inertial↔ITRF and Ṙ = 0 documented for inertial↔inertial; 3×3 position-only variants. Tests: GCRF→ITRF velocity block reflects the ω⊕ coupling and stays symmetric PSD (spec: "Rotating a covariance into ITRF"); GCRF→TEME→GCRF covariance round trip (spec: "Covariance round trip preserves the matrix"); GCRF→ITRF→GCRF state round trip to mm / µm-s⁻¹ (spec: "Round trip through the full chain").
- [ ] 2.5 Provider-seam tests: a custom test provider substitutes without call-site changes (spec: "Custom provider substitutes without call-site changes"); non-zero ΔUT1/polar-motion parameters measurably shift inertial↔ITRF results (spec: "Explicit EOP parameters are honored").
- [ ] 2.6 Free-function conveniences (`teme_to_gcrf`, `gcrf_to_itrf`, …) over the default provider; rustdoc examples compile (doc tests) and every public item documents its frame and scale conventions.
