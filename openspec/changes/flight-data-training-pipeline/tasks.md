## 5. Track B foundation — measurement synthesis + classical-tracker loop

> Per design.md Decision 4: ADS-B is system-level truth, not a measurement source. The IMM classifier must train on **filter outputs** (state estimates from the classical tracker) so its training distribution matches deployment. This phase wires truth → synth-measurements → classical tracker → filter-state-history into a training-ready dataset.

- [x] 5.1 Drive `thresh_synth::radar::measurements_from_trajectory` (Phase 4.2) over each canonical trajectory in the acquisition output, producing a stream of synthesised measurements per trajectory. _`thresh::training::generate_imm_training_samples` (`crates/thresh/src/training/mod.rs`) wraps a canonical trajectory in a `TargetTrack` and calls `measurements_from_trajectory`; radar returns `(range, az, el)` are inverted to Cartesian detections via `thresh_core::coords::spherical_to_cartesian` (same convention the synth forward model uses)._
- [x] 5.2 Run the classical tracker (`thresh-tracker` configured with the analytic IMM) over the synthesised measurement stream. Snapshot the per-step filter state and covariance. _Builds `MultiObjectTracker::new_imm_position(|| ImmConfig::cv_ca_ctrv_ct(..))` and steps it per tick; snapshots `track.state`/`track.covariance`/`dominant_mode` for every **confirmed** track (3-of-5)._
- [x] 5.3 Define a `filter_state_projection` that maps the full Kalman/IMM state and covariance into a fixed-size feature vector suitable as classifier input. ~~Default: state `[x, y, z, vx, vy, vz, ax, ay, az]` concatenated with the diagonal of the covariance (dim = 18).~~ Document the choice in `design.md` Open Questions and revisit if the classifier struggles. _Implemented as `thresh_filter::imm::project_filter_state` → **12-dim** `[x, vx, y, vy, z, vz]` ++ 6 covariance-diagonal entries. The IMM combine output is 6D common space (no acceleration), so the original 9-dim/18-dim assumption was infeasible without fabricating constants; see design.md Decision 14. `CLASSIFIER_FEATURE_DIM = 12`._
- [x] 5.4 Derive analytic mode labels per snapshot from the underlying trajectory kinematics (acceleration > 1 m/s² → CA; turn rate > 3°/s → CTRV; sustained turn rate > 3°/s with bank > 15° → coord_turn; else CV). Labels MUST come from the trajectory, not from the filter output. _`thresh_synth::mode_label::analytic_mode_label` (finite-difference accel + heading turn-rate). Bank is not stored in the trajectory, so it is derived from the balanced coordinated-turn relation `bank = atan2(|ω|·speed, g)`; turning is evaluated before acceleration so a turn's centripetal accel doesn't mislabel it CA. `MotionModeLabel` lives in `thresh-core`, index-aligned to the `cv_ca_ctrv_ct` bank._
- [x] 5.5 Write the resulting `(filter_state_history, analytic_mode_label_at_end)` examples to Parquet under `test-data/training/imm-classifier/` (sample only) and an external bucket (full). _**Rust-native** writer `thresh::training::parquet_export::write_imm_samples_parquet` behind the `training-export` feature (heavy `arrow`/`parquet` deps kept out of default/CI builds per project convention). The `gen-imm-dataset` binary produces the checked-in 440-row sample (~56 KB); verified readable by the project's `pyarrow`. Full-dataset trajectory ingestion is wired in Phase 6._
- [x] 5.6 Unit test: a constant-velocity trajectory yields labels that are 100% `CV`; a known coordinated-turn trajectory yields labels that are at least 80% `coord_turn` during the turn segment. _`mode_label::tests` (kinematics-only) covers both, plus straight-line→CA and a shallow-turn→CTRV (bank < 15°) discriminator. `training::tests` repeats the CV case end-to-end through synth + tracker._
- [x] 5.7 Smoke test: assert the filter-state input to the classifier dataset is NEVER drawn directly from an ADS-B state vector (only ever from a tracker filter output). This guard fails the build if the dataset pipeline is wired incorrectly. _`ensure_sensor_level` rejects any `Measurement::AdsB` before it can reach the tracker (`TrainingError::AdsbContamination`); features are read only from `track.state`. Test `guard_rejects_adsb_but_accepts_radar` plus a positive-covariance assertion (raw ADS-B state has no filter covariance)._
