# Tasks — Orbital & Ballistic Filter Models

> Phases follow design.md's Migration Plan: shared force math lands first and proves arithmetic identity before anything consumes it; the benchmark gate tightens last, once the tracker it measures exists. Golden-vector validation is spread through the phases (tier 1 with the state type, tier 2 with the filter models, tier 3 fixtures at the end); the reference doc (Phase 7) should land alongside Phases 1–3 because the Jacobian cross-check test cites it.

## 3. Filter motion models — `thresh-filter` (Decisions 3, 4, 6-mapping)

- [x] 3.1 Implement the shared `numeric_jacobian(f, x, dt, scales)` central-difference helper (per-column step `h_i = ε·max(|x_i|, s_i)`, `ε = cbrt(f64::EPSILON)`); unit-test it against `ConstantVelocity`'s exact `F`.
- [x] 3.2 Implement `KeplerJ2` (`models/kepler_j2.rs`): interleaved 6D ECI state, `predict` sub-steps `dt` with the shared closure-based RK4 (`n = ceil(dt / max_step_s)`, default 10 s), radius clamp below `equatorial_radius / 2` (never panic), WNA process noise blocks from `sigma_accel`, `jacobian` via `numeric_jacobian`.
- [x] 3.3 `KeplerJ2` filter tests: EKF, UKF, and CKF each predict one step from the same LEO state — mean consistent with Kepler+J2 propagation, covariance symmetric positive definite (spec: "Prediction through all three nonlinear filters"); construction with lunar mu uses the supplied mu throughout (spec: "Non-Earth gravitational parameter").
- [x] 3.4 Jacobian consistency test: numeric Jacobian vs `I + A(x)·dt + O(dt²)` at small dt using the analytic two-body+J2 `∂a/∂r` derived in the reference doc (spec: "Jacobian consistency"; cite the doc section in the test comment).
- [x] 3.5 Golden tier 2: Vallado Kepler-propagation worked example on `KeplerJ2` with J2 disabled (≤ 10 m); J2 nodal-regression test — multi-revolution LEO propagation matches the analytic RAAN drift rate within documented tolerance; truth-identity test — `KeplerJ2::predict` over a 60 s LEO arc vs `thresh_synth::propagate` with matched step agrees within 1e-6 m (enforces Decision 1's identical-physics claim).
- [x] 3.6 Implement `BallisticReentry` (`models/ballistic_reentry.rs`): 7D `[x, vx, y, vy, z, vz, β]`, dynamics `two_body + J2 + drag_acceleration(r, v, 1/β)` with `β̇ = 0`, β clamped to `beta_floor` inside `predict`, sub-stepped RK4 (`max_step_s` default 1 s), Q = 6D WNA blocks + `Q[6,6] = sigma_beta²·dt`, jacobian via `numeric_jacobian` with β column scale `max(|β|, 100.0)·ε`.
- [x] 3.7 `BallisticReentry` dynamics tests: drag deceleration magnitude equals `ρ(h)·v²/(2β)` directed opposite `v_rel` (spec scenario); above the atmosphere ceiling the drag term vanishes and prediction matches gravity-only propagation (spec: "Exoatmospheric limit"); EKF/UKF/CKF predict from a reentry-interface state with SPD covariance; a Jacobian unit test at a 100 km-altitude state (conditioning risk from design Risks).
- [x] 3.8 β positivity test: measurement updates that would drive β negative leave the effective β strictly positive via the floor (spec: "Beta stays positive").
- [x] 3.9 Implement `Reentry7Mapping: StateMapping` (drop/append β + covariance row/col, following the `CaMapping` pattern in `imm.rs`) with unit tests, so a boost(CA)/reentry bank is composable through public `ImmConfig`; the `cv_ca_ctrv_ct` bank and `MotionModeLabel` stay untouched (Decision 6 deferral, note in code comment).

## 4. Phased ballistic truth generation — `thresh-synth` (Decision 5)

- [ ] 4.1 Create `thresh-synth/src/ballistic.rs` with `BallisticProfile` (launch geodetics, azimuth, `thrust_accel`, `burn_time_s`, `pitch_over_s`, `pitch_kick_rad`, `beta`, epoch) and `generate(&BallisticProfile, dt) -> Vec<OrbitalState>` integrating in ECI with the shared closure-based RK4; phase-helper decomposition up front (`boost_accel`, `phase_of`, `integrate_profile`, each ≤ 15 complexity) with per-helper unit tests.
- [ ] 4.2 Boost phase: vertical rise until `pitch_over_s`, instantaneous downrange pitch kick, then zero-lift gravity turn with thrust aligned to `v_rel = v − ω_⊕ × r`; constant thrust acceleration (no mass depletion/staging).
- [ ] 4.3 Midcourse and reentry phases: midcourse acceleration closure is exactly `two_body + J2` (identical to `propagate` with `include_j2: true, drag: None`); reentry (altitude < 100 km descending) adds `drag_acceleration(r, v, 1/β)` — the same closure `BallisticReentry` integrates; terminate at the (spherically approximated) surface.
- [ ] 4.4 Output adapters: station-projection helper reusing `orbital_to_enu` / `eci_to_enu`, and a `TrajectoryPoint`-grid adapter so the radar generator consumes ballistic truth exactly like the SGP4 orbital source.
- [ ] 4.5 Delete `SegmentType::Ballistic { drag_coefficient }` (BREAKING) and migrate the two constructor sites — `trajectory.rs:289` and `crates/thresh/tests/integration.rs:179,191` — to `SegmentType::Ca { acceleration: [0.0, 0.0, -9.81] }` or a `BallisticProfile` as appropriate. Acceptance: `grep -r "SegmentType::Ballistic"` is clean workspace-wide.
- [ ] 4.6 Truth-generation tests: position and velocity continuous at both phase boundaries (spec: "Phased ballistic trajectory generation"); a long-range trajectory's ground track follows the round Earth and the impact point shifts with Earth rotation vs a non-rotating run (spec: "Round rotating Earth"); a midcourse segment's initial state propagated independently through `thresh_synth::propagate` matches the generator's midcourse states (spec: "Midcourse consistency with the orbital propagator").
- [ ] 4.7 Filter-vs-truth reentry validation: `BallisticReentry::predict` with the truth's initial state and true β reproduces a truth-generated reentry arc within a documented tolerance (spec: "Prediction matches truth with true beta").
- [ ] 4.8 β estimation test: an EKF with `BallisticReentry` tracking a truth-generated reentry with position measurements, starting from a β estimate biased ≥ 50% from truth, converges toward true β during the high-drag portion with substantially smaller final error (spec: "Beta convergence during high-drag flight").
